Architecture Layers
Data Structure
SinglyLinkedList.js · DoublyLinkedList.js
Pure JS classes. Real pointer-based logic. No React. Returns snapshots of each step.
State
useListStore.js
Zustand store holding the flat array of node objects that React renders.
Operations
useListOperations.js
Calls the DS class, gets snapshots back, plays them through the store with timed delays.
UI Components
ListCanvas · NodeCard · Arrow · ControlPanel · StepLog
Renders and animates the list. Narrates each step in plain language.
Key Concept — Snapshot Animation

Each DS operation returns an array of snapshots — the full list state at each meaningful step. A playback engine steps through them with a delay, so the UI animates the algorithm frame by frame.

This keeps algorithm logic completely separate from animation, and makes speed controls or manual step-through trivial to add later.

// each snapshot looks like this
{ nodes: [...], highlightedId: 'node-3', message: 'Value not found, moving on...' }

// node shape in the store
{ id: 'uuid', value: 42, next: 'uuid' | null, prev: 'uuid' | null }

How to Approach This Project
01
Build the DS classes first, completely separate from React
Write SinglyLinkedList.js as a plain JS class in isolation. Test it in the browser console. Make sure insert, delete, and search all work correctly with real pointers before you ever think about rendering anything.
02
Resist the urge to look things up too quickly
Try to reason through it from first principles first — what does a node need? What happens to pointers when you insert in the middle? What's the edge case when deleting the head? Struggling through that thinking is where the learning happens.
03
Use the React side as a reward, not a crutch
Once your DS class works correctly in isolation, building the visualizer becomes a fun way to prove your implementation is correct. If the animation shows something wrong, you have a bug in your DS class — the UI becomes your test suite.
04
Pay attention to edge cases
Empty list, single node, inserting/deleting at head vs. tail vs. middle, searching for a value that doesn't exist. These are where your real understanding gets tested and where linked lists get interesting.
05
When you get to doubly linked lists, don't just copy your singly linked list
Re-derive the logic. The prev pointer changes what you have to do on almost every operation, and working through that difference yourself is the whole point.
06
Finish one end-to-end before expanding scope
Nail singly linked list in JS → get it rendering statically in React → add operations → add animation → then repeat for doubly. Don't build both DS classes upfront. Have a working, satisfying thing before expanding.
